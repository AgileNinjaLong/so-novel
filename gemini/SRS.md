## 1. 引言

### 1.1 编写目的
本文档旨在明确“摸鱼看小说软件”（代号：NovelRead）的产品需求、功能范围、摸鱼隐蔽性设计及非功能性需求，为后续系统架构设计（SDS）及代码开发提供明确指南。

### 1.2 背景与痛点
在日常办公环境中，上班族在工作间隙有阅读小说的需求，但传统阅读器存在以下痛点：
1. **窗口目标大**：界面明显，极易被同事或领导察觉。
2. **缺乏防偷窥机制**：紧急情况下无法一秒隐藏或伪装。
3. **格式支持单一**：市面上很多轻量摸鱼工具仅支持纯文本 TXT，不支持带目录结构的 EPUB/MOBI。

## 3. 摸鱼场景与核心功能需求

### 3.1 摸鱼外观模式 (Stealth Modes)
系统必须提供至少 **三种摸鱼伪装外观模式**，用户可自由一键切换：

1.  **极简透明悬浮窗模式 (Floating Strip Mode)**：
    *   无边框透明窄条窗口，置顶显示。
    *   支持调节透明度（0%~90%）与背景融合。
    *   支持单行/双行滚动显示。
2.  **IDE / 终端伪装模式 (Dev/IDE Pseudo Mode)**：
    *   界面伪装为 VS Code 调试日志、终端控制台或 Git 编译输出。
    *   小说文字混入代码注释或日志信息中展示。
3.  **Office / 日志伪装模式 (Office/Log Pseudo Mode)**：
    *   伪装成 Excel 单元格或系统运行日志。

### 3.2 应急安全机制 (Safety & Boss Keys)
1.  **全局老板键 (Boss Key)**：
    *   按下默认全局快捷键（如 `Alt + Space` 或 `Esc`），窗口**瞬间隐藏**至后台静默运行（无任务栏图标/托盘可选静默）。
    *   再次按下快捷键恢复阅读状态。
2.  **鼠标划出/失焦自动隐藏/透明化**：
    *   当鼠标离开阅读窗口范围，窗口自动降为极低透明度或切换为假日志。

### 3.3 电子书格式支持 (Format Parsing)
系统必须支持以下常见小说格式解析与展示：
1.  **TXT 格式**：
    *   自动识别编码（UTF-8, GBK, GB2312, UTF-16 等），避免乱码。
    *   智能正则匹配章节目录（如 `第X章`、`Chapter X`）。
2.  **EPUB 格式**：
    *   解析 HTML/XHTML 章节文本，提取完整目录树（TOC）。
    *   滤除无关样式，提取纯文本用于摸鱼展示。
3.  **MOBI / AZW3 格式**：
    *   解析文件基础目录与章节纯文本。
4.  **PDF 格式（可选纯文本提取）**：
    *   抽取 PDF 页面中的文本内容流。

### 3.4 快捷键与模式自定义绑定
1.  **按键解绑与自定义 (Custom Key Bindings)**：
    *   取消硬编码的模式切换按键（如原先固定的 `F12` 循环切换）。
    *   用户可为**每一个独立的摸鱼模式**（透明悬浮窗、IDE 伪装、CAD 伪装）绑定专属的局部唤醒快捷键（如 `Ctrl+1`, `Ctrl+2`, `Ctrl+3`）。
    *   用户可重设全局“老板键”快捷键（如 `Alt+Z` 改为 `Esc` 或其他组合）。
2.  **设置管理界面 (Settings GUI)**：
    *   提供一个专门的可视化设置面板（通过右键菜单 `⚙️ 设置` 调出）。
    *   面板内允许用户直接通过键盘录入捕获想要的快捷键组合。
    *   具备**防冲突检测机制**：若用户将某一模式快捷键与老板键或另一模式的快捷键设为相同，界面需给出红字警示并阻止保存。

### 3.5 SoNovel 聚合下载与多格式合并模式 (SoNovel Integration & Export Modes)
1. **对齐 SoNovel 完整书源规则库**：
   * 必须载入包含 `main.json`、`cloudflare.json`、`no-search.json`、`proxy-required.json`、`rate-limit.json` 在内的全量规则库。
   * 支持针对不同站点规则的频率限制 (`rate-limit`) 与代理路由控制。
2. **可选合并模式 (Optional Export / Merge Modes)**：
   * **TXT 单文件合并**：将小说全本章节合成为单个 `.txt` 文本文件。
   * **EPUB 电子书合成**：支持将下载的章节直接打包合成为标准的 `.epub` 电子书文件（带完整的 TOC 目录与 HTML 样式）。
   * **按章节独立拆分**：将各个章节保存为独立的 `.txt` 文件存放于对应的小说目录中。
3. **搜书结果稳定性与确定性排序 (Deterministic Search Ranking)**：
   * 搜书结果必须依据（匹配度 Scoring > 书源优先级 > 书名）进行稳定确定性排序。
   * 解决多次搜索因线程并发返回顺序随机导致列表顺序撕裂、二次搜索结果不一致的问题。

## 4. 非功能性需求

1.  **性能与资源消耗**：
    *   启动时间 < 1.5 秒。
    *   静置/阅读时内存占用低于 **40MB**，CPU 占用低于 1%。
2.  **数据安全与隐私**：
    *   所有电子书解析与阅读记录完全存储在本地（如 SQLite 或 JSON 配置文件），不上传任何云端服务器。
3.  **易用性**：
    *   支持拖拽文件直接打开阅读。

## 5. 软件测试需求规格

### 5.1 单元测试要求 (Unit Testing Requirements)
1. **测试框架**：使用 `pytest` 自动化测试框架。
2. **核心覆盖模块**：
   * **编码识别助手 (`utils/encoding.py`)**：确保 UTF-8, GBK, GB2312, UTF-16, ASCII 识别准确率达 100%。
   * **电子书解析引擎 (`core/parser.py`)**：
     * TXT 分章正则匹配测试（带目录/不带目录格式）。
     * EPUB 容器解包与 HTML 纯文本提取测试。
     * PDF 页面文本抽离测试。
   * **配置与进度持久化 (`core/config.py`)**：断电/异常退出时配置恢复与读写正确性。
3. **单元测试代码覆盖率**：核心 Parsing 与 Utility 模块代码行覆盖率达 **85%** 以上。

| **TC-BB-01** | 全局老板键 | 各种模式下按下全局快捷键 (`Alt+Z`) | 窗口在 <100ms 内完全隐形，任务栏无残留 | P0 |
| **TC-BB-02** | 极简悬浮窗 | 鼠标移入/划出窗口 | 窗口透明度自动按设定（如从 0.2 到 0.85）渐变恢复 | P1 |
